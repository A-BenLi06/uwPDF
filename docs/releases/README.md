# Release notes

Before pushing `v<major>.<minor>.<build>.<revision>`, add a matching
`docs/releases/v<version>.md` to the source commit.

Start with new features and user-visible improvements, then fixes, installation
guidance and known limitations where applicable. The workflow appends the source
commit, source ref, toolchain and validation scope in a final Developer information
section. Do not put signing secrets, private keys or local Store upload containers
in this directory.
